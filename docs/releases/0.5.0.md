Fifth release of **skywatch-cyd**.

## New
- **WiFi setup mode.** A board with no WiFi saved, or that cannot reach its WiFi for 3 minutes, opens its own
  WiFi (`skywatch-XXXX`, with a random password shown on the screen) and a settings page that phones open by
  themselves: WiFi, location, radius, seconds per plane and night mode. The screen shows a QR code to join,
  the network name, the password and `192.168.4.1`. Start it by hand with `setup` over serial, or by holding the
  board's button for 3 seconds. It ends by itself once the board is connected.
- **TTGO T-Display** and **M5StickC** support, both tested on real hardware. Their small screens show the
  plane, the compass and one value at a time (distance, altitude, speed); the button shows the next plane.
- `set plane <seconds>`: how long each plane stays on screen (default 6), shared between the values on small
  screens. `set max <planes>`: the most planes shown, nearest first (default 10, up to 20).
- `version` prints the firmware version, build date and board; `update` asks GitHub whether a newer release exists.
- Message screens ("No aircraft in range"...) shrink to fit narrow screens.

- **Web page and MCP server on the board** (on by default, each with its own off switch: `set web off`,
  `set mcp off`, `set advertise off`, the setup page or the portal's setup form); the board makes an access
  token (`token` shows it) and serves nothing without it.
  **Updating an installed board turns both on too** (it makes its token on the first start; read it with
  `token` over USB serial). To close the port completely: `set web off` and `set mcp off`. The web page at
  `http://skywatch.local/` shows the planes and the settings; `/mcp` is a read-only MCP endpoint
  (`get_nearby_flights`, `get_current_plane`, `get_status`) for AI assistants. Everything needs the token, browser
  requests to `/mcp` are refused and five wrong tokens lock the board out for a minute. The board announces
  `_mcp._tcp` over mDNS and serves a Server Card (`/mcp/server-card`) and an AI Catalog
  (`/.well-known/ai-catalog.json`), which hold no secret. Tested in the esp32sim emulator and by host tests, not
  yet on a real board.

- **MCP header authentication** (`set mcpauth on`, off by default): `Authorization: Bearer <token>` or `X-API-Key`.
  Off, anyone on your network can read the planes and status through MCP (read-only); the web page and the
  settings always need the token.
- **ESP8266 + OLED board** (`esp8266-oled`, tested on one ESP-12 board with the OLED on GPIO 14/12): the same text display
  as the OLED builds, from a separate build that shares the flight parsing and settings commands with the ESP32 build.
  One image at 0x0 (install and update are the same file; settings are kept). Text only, no web page or MCP server;
  memory is tight there.
- **Route on the small screens:** the T-Display and M5StickC rotate distance, altitude, speed and the route; the OLED
  alternates the route with the airline row.
- **Better fetching on every board:** the aircraft list is parsed straight off the connection instead of being
  collected in a string first (lower peak memory; in the emulator 15 good fetches out of 15 against about half).
- **Fix: the board restarted itself every ~10 minutes after boot** (a wrapped timer in the stuck-fetch check).
  Found by the new emulator test.

## Boards
| Board | `<board>` | Status |
|---|---|---|
| Cheap Yellow Display 2.8" (ILI9341) | `cyd` | tested on real hardware |
| Cheap Yellow Display 2.8", two USB ports (ST7789) | `cyd-st7789` | not tested on hardware |
| 3.5" "big CYD" (ST7796) | `cyd35` | experimental |
| LilyGO TTGO T-Display | `ttgo-tdisplay` | tested on real hardware |
| M5StickC (original) | `m5stickc` | tested on real hardware |
| Waveshare ESP32-S3-Touch-AMOLED-1.8 | `amoled18` | emulator only |
| ESP32 + 0.96" OLED module | `oled96` | not tested |
| ESP32 with a built-in 0.96" OLED | `oled96-onboard` | experimental |
| ESP8266 with a built-in 0.96" OLED | `esp8266-oled` | experimental (one board tested) |

Flash from the [web portal](https://joao-m-ferreira.github.io/skywatch-cyd/) or with the `-merged.bin` for
your board at `0x0` (`--chip esp32s3` for the AMOLED board). Verify the downloads against `SHA256SUMS`.
The M5StickC C Plus and Plus2 have other screens and are not supported yet.
