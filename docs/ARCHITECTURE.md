# Architecture

```
adsb.fi open data --HTTPS--> firmware/ (ESP32 CYD, standalone) --> screen
```

The ESP32 is standalone: no companion server is needed. `service/` is an optional,
independent Go proxy that serves the same data as compact JSON; the firmware does not use it.

- `service/` (optional, unused by the firmware): `GET /v1/flights?lat&lon&radius_km&n` fetches adsb.fi (15 s cache, last-good on failure, coordinates rounded to ~1 km upstream), validates the payload, drops ground/no-position aircraft, returns the nearest `n` as `{"f":[{cs,ty,rg,alt,spd,trk,km,brg}]}`. Optional `X-Token` via `API_TOKEN`.
- `firmware/jf_flight_display/`: `board.h` (pins), `flights.{h,cpp}` (ADS-B parsing + formatting), `silhouette.{h,cpp}` (table of ~100 aircraft types with real length, span, sweep, engines and mounting; class defaults for unknown types) and `model3d.{h,cpp}` (builds a ~850-triangle 3D mesh from that table: lofted fuselage with 747 hump / A380 double deck, cockpit glass (neo "raccoon mask"), windows and doors as overlays, swept tapered wings with type-specific winglets (fences, sharklets, blended, split scimitar, canted), tailplane, a fin gridded so a per-airline tail design can be painted on it, pylon-mounted engines (2, 3, 4 or 6), propellers or a rotor; then projects it with perspective and flat Lambert shading, painter's-algorithm sorted, with a dark 1 px outline, mirrored to face the direction of flight; geometry the fixed camera never sees is not built (right side and belly of the fuselage, far-side windows, the fin's far face, wing undersides), which frees triangles for visible detail; the mesh, projection and screen-triangle buffers are allocated once on first use and never freed (per-draw malloc fragmented the heap and left the panel blank after a while; static buffers overflowed DRAM), ~190 ms per plane) and `photos.{h,cpp}` (optional photo of the actual aircraft from planespotters.net by registration: thumbnail JPEG, 4 cached in RAM, prefetched for the next plane, decoded straight to the screen with a 3/4 nearest downscale, photographer credited; falls back to the 3D model; requires `PLANESPOTTERS_CONTACT` in secrets.h) and `livery.h` (tail designs, fuselage schemes, tints; per-airline rows in `airline.cpp`), `airline.{h,cpp}` (callsign prefix to airline name and brand colours, ~140 operators; unknown prefixes show the operator code), all host-tested; `plate.{h,cpp}` (the plate screen), `display.h` (LovyanGFX setup), `jf_flight_display.ino` (WiFi, polling, touch, LDR). The ESP32 queries `opendata.adsb.fi` directly, reading the body into memory and parsing it with an ArduinoJson filter (parsing straight from the TLS stream proved unreliable) and computing distance, bearing and the nearest-N on device. TLS certificate validation is skipped (`setInsecure`) because only public read-only data is fetched and no credentials are sent.
- `firmware/test/`: host unit tests built with g++ against ArduinoJson.
- `scripts/`: build, test, lint, packaging and the emulator smoke test (see CONTRIBUTING.md); `check_*.py` are the docs and release-artifact checks.

Decisions: C++ over MicroPython (compile-time checks, CI); standalone ESP32 (user requirement; no server to keep running), with the Go service kept as an optional proxy; no code copied from references (licences). See `docs/PRD.md`.
